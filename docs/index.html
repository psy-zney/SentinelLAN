3 Trụ Cột Chiến Lược Triển Khai

SentinelLAN được cấu trúc để linh hoạt đáp ứng mọi quy mô triển khai của doanh nghiệp, cơ quan và cộng đồng kỹ thuật.

🏢

1. Tự Host Nội Bộ (Self-Hosted)

Dành cho doanh nghiệp, cơ quan, phòng lab muốn kiểm soát 100% dữ liệu trên máy chủ văn phòng mà không phụ thuộc Internet.

  • Triển khai 1 lệnh qua Docker Compose stack chuẩn hóa.
  • Dữ liệu lưu trữ nội bộ trên PostgreSQL cục bộ an toàn.
  • Agent kết nối trực tiếp trong mạng LAN / Wi-Fi văn phòng.
  • Miễn phí, không rò rỉ dữ liệu vận hành ra bên ngoài.

2. Mã Nguồn Mở (Open-Source)

Cung cấp mã nguồn sạch, kiến trúc chuẩn Modular Monolith / Clean Architecture để cộng đồng dễ dàng audit và đóng góp.

  • Backend .NET 10 (C# 14) & Frontend Next.js 16 (React 19).
  • Ranh giới phân tầng Domain, Application, Infra độc lập.
  • Quy chuẩn kiểm thử tự động xUnit, Vitest, Playwright E2E.
  • Không dính líu bản quyền độc quyền hay vendor lock-in.

3. Cloud VPS & Multi-Tenant SaaS

Dành cho việc kinh doanh dịch vụ quản lý đa công ty (SaaS) và quản trị máy chủ Cloud Linux qua kết nối SSH an toàn.

  • Cô lập đa tổ chức (Multi-Tenant) 4 lớp nghiêm ngặt.
  • Quản trị VPS từ xa bằng OpenSSH Private Key + IPv4.
  • Kho bảo vệ Private Key mã hóa bằng AES-256-GCM Vault.
  • Thu thập CPU, RAM, Disk, danh sách Docker container.

Engineering Workflows

Sơ Đồ 8 Luồng Hoạt Động Chi Tiết (E2E)

Mô tả chi tiết từng bước chuyển trạng thái, mã phản hồi và cơ chế an toàn trong từng luồng nghiệp vụ.

Luồng 1: Xác Thực Danh Tính & Khóa Phiên Tức Thì (Session Lifecycle & Instant Lockout)

Quy trình đăng nhập bảo mật với băm mật khẩu PBKDF2-SHA256, cấp Access Token trong HttpOnly Cookie, xoay vòng Refresh Token (Token Rotation) và cơ chế khóa tài khoản có hiệu lực ngay lập tức với phiên đang dùng.

01
Gửi Form Đăng Nhập
Người dùng nhập Mã tổ chức (OrgCode), Email và Password. Gửi HTTPS POST tới endpoint xác thực. Áp dụng Rate Limiting tối đa 10 lần/phút/IP. Chặn demo credentials ở Production.
POST /api/v1/auth/login
02
Kiểm Tra PBKDF2-SHA256
Backend truy vấn User theo OrgCode và Email. Xác thực mật khẩu qua PBKDF2 với 100,000 vòng lặp và Salt 16 bytes. Chống tấn công Rainbow Table. Kiểm tra cờ IsLocked.
Pbkdf2PasswordHasher.Verify()
03
Cấp HttpOnly Cookies
Cấp Access Token (hạn 15 phút) và Refresh Token (hạn 7 ngày) được gán cờ HttpOnly, Secure, SameSite=Strict. JavaScript tuyệt đối không thể đọc token.
Set-Cookie: sentinellan_access=...
04
Khóa Tài Khoản Tức Thì
Khi Admin khóa tài khoản (IsLocked = true), Server thu hồi toàn bộ Refresh Session và đánh dấu thu hồi Access Token trong SessionRevocations. Phiên đang mở lập tức bị từ chối ở request kế tiếp.
SessionRevocation: Instant Kick

Luồng 2: Bắt Tay & Ghi Danh Thiết Bị (Agent Enrollment Handshake)

Cơ chế cấp token dùng 1 lần (Single-Use Token), trao đổi khóa đối xứng cho máy trạm và lưu trữ an toàn trong Windows DPAPI phần cứng.

01
Cấp Token Ghi Danh
Admin cấp Token trên Dashboard. Hệ thống sinh 32 bytes ngẫu nhiên qua CSPRNG, hạn sử dụng 15–60 phút và chỉ lưu bản băm SHA-256 vào Database.
POST /api/v1/enrollment-tokens
02
Agent Gửi Yêu Cầu
Agent trên máy nhân viên gửi HTTP POST kèm Token thô và dấu vân tay phần cứng (Hostname, OS Version, MAC Address). Không mở bất kỳ cổng lắng nghe nào.
POST /api/v1/agent/enroll
03
Hủy Token Nguyên Tử
Server kiểm tra token hợp lệ -> Hủy token ngay lập tức trong 1 transaction (IsRevoked = true) -> Cấp Device ID và Device Secret riêng cho thiết bị.
Atomic Transaction (No Reuse)
04
Lưu Khóa DPAPI Phần Cứng
Agent mã hóa Device Secret vào Windows DPAPI phần cứng. Server phát sự kiện SignalR giúp máy tính hiện đèn XANH Online tức thì trên Dashboard.
DPAPI ProtectedData.Protect()

Luồng 3: Thu Thập Telemetry & Ping Heartbeat Định Kỳ (30 Giây)

Chu kỳ thu thập số liệu phần cứng tối thiểu, khử trùng lặp dữ liệu qua Idempotency-Key và phát sóng thời gian thực qua WebSocket SignalR.

01
Đo Đạc Thông Số Tối Thiểu
Agent Worker định kỳ đo % CPU, % RAM, % Disk và Uptime. Tuyệt đối không đọc file người dùng, không quét lịch sử duyệt web hay chụp màn hình.
ITelemetryCollector.Collect()
02
Gửi Heartbeat Xác Thực
Gửi payload kèm IdempotencyKey qua header X-SentinelLAN-Device-Id và X-SentinelLAN-Device-Secret. Chống ghi trùng lặp dữ liệu khi mạng lag.
POST /api/v1/agent/heartbeat
03
Ghi Snapshots & So Ngưỡng
Server lưu lịch sử sử dụng phần cứng vào bảng TelemetrySnapshots, cập nhật trường LastSeenUtc và so sánh ngưỡng cảnh báo (Alert Policy).
PostgreSQL: TelemetrySnapshots
04
Phát Sóng SignalR Realtime
Server phát sự kiện qua WebSocket tới riêng nhóm Tenant đó. Biểu đồ thông số kỹ thuật trên màn hình Dashboard cập nhật ngay lập tức không cần tải lại trang.
SignalR: TenantGroup(orgId)

Luồng 4: Hàng Đợi Ngoại Tuyến & Tự Phục Hồi Khi Mất Mạng (Offline Queue Resilience)

Production giữ tối đa 50 heartbeat trong file mã hóa (DPAPI trên Windows, AES-GCM trên Linux) và khôi phục queue sau restart. Development mặc định dùng RAM. Retry dùng exponential delay với jitter ±500 ms, clamp 2–60 giây.

01
Phát Hiện Ngắt Kết Nối
Khi request Heartbeat gặp lỗi mạng (DNS failure, timeout, HTTP 503), Agent chuyển sang chế độ Offline Mode và kích hoạt hàng đợi đệm cục bộ.
AgentState: Disconnected
02
Queue Có Giới Hạn và Lưu Bền Trong Production
Production lưu tối đa 50 heartbeat trong file được bảo vệ: DPAPI trên Windows, AES-GCM trên Linux. Queue loại mục quá một giờ; Development mặc định giữ queue trong RAM.
ProtectedOfflineTelemetryQueueStore · capacity 50
03
Exponential Delay + Jitter Nhỏ
Worker bắt đầu với delay 5 giây; sau lỗi mạng tăng gấp đôi mỗi lần, cộng/trừ tối đa 500 ms rồi giới hạn trong 2–60 giây. Đây không phải Full Jitter.
Worker retry · clamp 2–60s · ±500ms
04
Xả Hàng Đợi (Drain Queue)
Khi gửi thành công, Agent lấy lần lượt các mục trong hàng đợi và gửi như heartbeat thông thường kèm Idempotency-Key. Không có endpoint bulk hoặc cờ IsBuffered trong luồng này.
POST /api/v1/agent/heartbeat

Luồng 5: Lệnh Điều Khiển Ký Số Mật Mã (Safe Simulated Commands)

Mỗi lệnh điều khiển bắt buộc có lý do, quyền Admin/Technician, thời hạn hiệu lực ngắn (TTL), kèm chữ ký số HMAC-SHA256 10 tham số chống can thiệp và chống phát lại.

01
Admin Tạo Lệnh
Chọn lệnh allow-list (SimulateLock, RestartService, ShowNotification), điền lý do bắt buộc và xác nhận. Thời hạn hiệu lực nghiêm ngặt 30–900 giây.
POST /api/v1/commands
02
Ký Số HMAC 10 Tham Số
Server ký HMAC-SHA256 bao phủ: [CommandId, OrgId, DeviceId, UserId, Type, Reason, IssuedAt, ExpiresAt, Nonce, Parameter]. Lưu trạng thái Pending.
HmacCommandSigner.Sign()
03
Agent Polling & Xác Thực
Agent nhận lệnh qua polling: Kiểm tra chữ ký khớp, kiểm tra thời hạn và kiểm tra Nonce chống Replay Attack. Nếu sai lệch -> Hủy lệnh và ghi cờ cảnh báo.
CommandVerifier.Verify()
04
Thực Thi & Trả Biên Lai
Lệnh hiện trả kết quả mô phỏng. Agent gửi trạng thái thành công/thất bại và message qua Device ID/Secret authentication; receipt không có chữ ký HMAC riêng.
POST /api/v1/agent/commands/{id}/result

Luồng 6: Quản Trị Cloud VPS Nâng Cao: SSH Host Key Pinning & Nonce Reservation

Giám sát và vận hành máy chủ Linux từ xa với khóa OpenSSH mã hóa AES-256-GCM Vault, bắt buộc so khớp vân tay Host Key (SHA-256 Pin) chống MitM, và đặt trước Nonce trong PostgreSQL trước khi Restart Service.

01
Đăng Ký & Host Key Pinning
Admin nhập IPv4, Port 22, Username, Private Key và bắt buộc nhập SHA-256 Host Key Fingerprint đã xác minh. Node cũ thiếu fingerprint bị chặn kết nối.
POST /api/v1/vps-nodes (Pin Required)
02
Mã Hóa AES-256-GCM Vault
Server mã hóa Private Key bằng thuật toán AES-256-GCM với Master Vault Key trước khi lưu DB. Database chỉ chứa bản mã vô nghĩa, tuyệt đối không lưu plain-text.
VpsVaultService.Encrypt()
03
Bắt Tay SSH & So Vân Tay Pin
Khi kết nối, SSH.NET chặn bắt tay nếu Host Key máy chủ không khớp byte-for-byte với Fingerprint đã pin trước đó, ngăn chặn 100% tấn công Man-in-the-Middle.
SSH HostKey Match: SHA256 Pin
04
Restart Service & Dành Nonce DB
Restart service VPS cần lý do, xác nhận, nonce và hạn ngắn (tối đa 5 phút). PostgreSQL ghi nhận Nonce bằng unique index trước khi lệnh SSH được thực thi, chống replay và race condition.
PostgreSQL: ReserveNonce()

Luồng 7: Quản Trị Tài Sản ITAM, Quét Mã QR & Kích Hoạt Thiết Bị

Quy trình quản lý vòng đời tài sản thiết bị cứng, sinh nhãn QR, quét camera WebRTC di động và kích hoạt liên kết tài khoản nhân viên.

01
Đăng Ký Tài Sản & Nhãn QR
IT tạo nhãn QR với mã opaque ngẫu nhiên. Server chỉ lưu hash, cùng tenant, thiết bị, hạn dùng tùy chọn và trạng thái thu hồi; payload QR không được ký HMAC.
POST /api/v1/asset-management
02
Quét QR Bằng Camera WebRTC
Kỹ thuật viên hoặc nhân viên dùng điện thoại mở trang /scan. Trình duyệt mở luồng Camera giải mã tức thời mà không cần cài đặt phần mềm bên ngoài.

Engineering Techniques

Kỹ Thuật Hệ Thống & Nguyên Lý Thiết Kế

Các chuẩn mực công nghệ được áp dụng nhằm đảm bảo độ tin cậy, an toàn thông tin và hiệu năng vận hành.

🔒 1. Zero Trust Endpoint Model

Áp dụng chuẩn NIST SP 800-207: "Never Trust, Always Verify". Máy trạm và máy chủ không mặc định tin tưởng nhau.

  • Mọi yêu cầu đều phải mang Header xác thực máy (Device Secret) hoặc HttpOnly Cookie.
  • Token ghi danh chỉ dùng 1 lần và tự hủy sau khi bắt tay.
  • Thiết bị không mở bất kỳ port inbound nào, loại bỏ 100% rủi ro bị scan port trong LAN.

🏢 2. Multi-Tenant 4-Layer Isolation

Cô lập đa tổ chức hoàn toàn từ giao diện tới tầng lưu trữ cơ sở dữ liệu:

  • Lớp 1: Context nhận diện Tenant qua Cookie / Subdomain.
  • Lớp 2: RBAC Authorization Policy phân quyền Admin / Tech / Employee.
  • Lớp 3: Store/service truyền organization scope tường minh vào truy vấn; hiện chưa có EF Core Global Query Filter.
  • Lớp 4: Partial Unique Index ở mức Engine DB ngăn chặn chồng chéo dữ liệu.

📜 3. Application-Level Append-Only Audit Guard

Nhật ký kiểm toán bất biến chống chối bỏ (Repudiation Prevention):

  • SentinelDbContext.SaveChanges từ chối entity AuditLog ở trạng thái Modified hoặc Deleted qua DbContext này.
  • Bất kỳ cố gắng sửa hay xóa nhật ký đều kích hoạt InvalidOperationException.
  • Ghi nhận định danh Actor, Target Device, Action, Nonce và UTC Timestamp.

🔄 4. Outbound Reverse Telemetry

Kiến trúc kết nối ngược bảo vệ an ninh mạng văn phòng:

  • Agent chỉ khởi tạo kết nối chiều đi (Outbound TCP) tới Server qua HTTPS port 443.
  • Vượt qua an toàn mọi thiết bị NAT Firewall, router văn phòng mà không cần cấu hình Port Forwarding.
  • Hạn chế tối đa bề mặt tấn công (Zero Attack Surface).

🔑 5. Windows DPAPI Machine Key

Bảo vệ khóa bí mật thiết bị trên máy trạm bằng phần cứng OS:

  • Sử dụng Windows Data Protection API (DPAPI) với cờ DataProtectionScope.LocalMachine.
  • Khóa được mã hóa bằng master key của hệ điều hành, gắn chặt với chip máy tính.
  • Kể cả khi bị copy file cấu hình sang máy tính khác, kẻ xấu cũng không thể giải mã.

📷 6. In-Browser WebRTC Camera Scanner

Quét mã QR trực tiếp trên trình duyệt không cần ứng dụng cài thêm:

  • Sử dụng API tiêu chuẩn navigator.mediaDevices.getUserMedia lấy luồng video.
  • Render luồng video lên HTML5 Canvas ẩn để bóc tách ma trận điểm ảnh.
  • Hỗ trợ BarcodeDetector API gốc hoặc ZXing Engine chạy thuần trong RAM.
Algorithms & Math

Chi Tiết Các Thuật Toán Hệ Thống

Mô hình toán học, thuật toán mật mã và cơ chế lấy mẫu phần cứng được áp dụng trong mã nguồn.

🔐 1. Thuật Toán Băm Mật Khẩu PBKDF2-SHA256

Áp dụng khuyến nghị NIST SP 800-132 để băm mật khẩu người dùng với chi phí tính toán cao, vô hiệu hóa phần cứng GPU cracking.

DK = PBKDF2(HMAC-SHA256, Password, Salt, iterations=100000, dkLen=32)
  • Salt: 16 bytes sinh ngẫu nhiên qua CSPRNG riêng biệt cho từng người dùng.
  • Số vòng lặp: 100,000 vòng HMAC-SHA256 kéo dài thời gian tính toán.
  • Format lưu trữ: pbkdf2:v1:100000:{salt_base64}:{hash_base64}.

⚡ 2. Chữ Ký Lệnh HMAC-SHA256 10 Tham Số

Bảo vệ tính toàn vẹn của lệnh điều khiển gửi tới Agent, chống can thiệp (Tampering) và chống phát lại (Replay Attack).

Signature = HMAC-SHA256(Key, UTF8(JsonSerialize([10 values])) )

JSON serialization của mảng 10 giá trị:

JSON array: [CommandId, OrganizationId, DeviceId, IssuedByUserId, Type, Reason, IssuedAtMs, ExpiresAtMs, Nonce, Parameter]
  • Nếu bất kỳ 1 byte nào trong 10 tham số bị thay đổi, chữ ký sẽ không khớp.
  • Agent kiểm tra: DateTime.UtcNow <= ExpiresAtUtc và kiểm tra Nonce chưa từng thấy.

🛡️ 3. Mã Hóa Khóa Riêng Tư AES-256-GCM Vault

Mã hóa xác thực với dữ liệu liên kết (AEAD) dùng để bảo vệ SSH Private Key của các VPS quản trị từ xa.

Ciphertext, Tag = AES-GCM-Encrypt(Key_256, Nonce_96, PlaintextKey)
  • Khóa đối xứng: 256-bit tạo từ SHA-256 của Master Vault Key.
  • Nonce: 96-bit (12 bytes) ngẫu nhiên cho mỗi lần mã hóa.
  • Authentication Tag: 128-bit (16 bytes) phát hiện ngay lập tức nếu bản mã bị can thiệp.

📈 4. Exponential Delay với Jitter Nhỏ

Thuật toán lùi thời gian kết nối lại khi mạng gặp sự cố, loại bỏ hiện tượng "Thundering Herd" làm sập máy chủ.

delay = clamp(previousDelay * 2 ± random(0..500ms), 2s, 60s)
  • Delay ban đầu: 5 giây.
  • Giới hạn: Delay được clamp trong khoảng 2–60 giây.
  • Giới hạn hiện tại: Worker chỉ cộng/trừ ngẫu nhiên tối đa 500 ms quanh exponential delay; chưa triển khai Full Jitter.

⏱️ 5. Thuật Toán Lấy Mẫu CPU Delta Sampler

Tính toán tỷ lệ sử dụng CPU thực tế qua chênh lệch thời gian Kernel và User của hệ điều hành giữa 2 chu kỳ:

% CPU = 100 * (1.0 - ΔIdleTime / (ΔKernelTime + ΔUserTime))
  • Windows: Gọi Win32 P/Invoke GetSystemTimes.
  • Linux: Đọc chênh lệch trường user + nice + system trên /proc/stat.
  • Độ chính xác cao, tải nhẹ, không tạo tiến trình con tốn tài nguyên.

⚖️ 6. Ràng Buộc Phân Công 1:1 Partial Unique Index

Đảm bảo về mặt toán học và cơ sở dữ liệu: Mỗi nhân viên chỉ được gán tối đa 1 máy tính đang hoạt động tại 1 thời điểm.

CREATE UNIQUE INDEX ix_assigned_user ON "Devices" ("AssignedUserId")
WHERE "AssignedUserId" IS NOT NULL AND "IsRevoked" = FALSE;
  • Cho phép 1 nhân viên có nhiều bản ghi thiết bị đã bị thu hồi (IsRevoked = true).
  • Chặn đứng tình trạng gán nhầm 1 nhân viên sở hữu 2 máy cùng lúc ở mức Database Engine.

✅ Đã Hoàn Tất & Kiểm Chứng Kỹ Thuật

  • Chặn Demo Credential Ở Production: Ở môi trường Production, hệ thống cấm nạp dữ liệu mẫu/mật khẩu demo. Bắt buộc nạp tài khoản quản trị đầu tiên qua biến môi trường bí mật.
  • Khóa Tài Khoản Hiệu Lực Tức Thì: Khi tài khoản bị khóa (IsLocked), toàn bộ phiên làm việc của người dùng bị thu hồi ngay lập tức qua bảng SessionRevocations, vô hiệu hóa Access Token đang dùng.
  • Luồng QR Theo API Thật: Mã opaque ngẫu nhiên chỉ trả khi phát hành; database lưu hash, tiền tố, hạn dùng tùy chọn và trạng thái thu hồi. Payload QR không có chữ ký HMAC.
  • SSH Host Key Verification (Pinning): Quản trị Cloud VPS bắt buộc nhập vân tay SHA-256 Host Key đã xác minh; mọi phiên SSH so khớp byte-for-byte; các node cũ thiếu pin bị từ chối kết nối.
  • Two-Phase Nonce VPS Restart: Thao tác Restart Service trên VPS yêu cầu xác nhận, lý do, nonce và hạn ngắn (tối đa 5 phút); Nonce được dành trước trong PostgreSQL bằng unique index trước khi chạy lệnh.
  • Sửa Nhãn Lệnh Mô Phỏng Trung Thực: Các nhãn mô tả lệnh của Agent thể hiện rõ ràng bản chất mô phỏng an toàn (SimulateLock, SimulateNetworkIsolation), không gây hiểu nhầm là đã can thiệp OS thật.

⚠️ Các Giới Hạn Cần Kiểm Chứng Trước Production

  • Hàng Đợi Bền Vững Cần Kiểm Chứng Trên Host: Production code lưu queue giới hạn 50 mục và nonce cache vào file được mã hóa, Development dùng RAM. Linux cần khóa riêng SENTINELLAN_AGENT_STORE_KEY; cần xác minh restore sau restart trên từng OS/runtime triển khai.
  • Lệnh Khóa / Cô Lập OS Vẫn Cố Ý Chỉ Mô Phỏng: Các lệnh SimulateLock và SimulateNetworkIsolation vẫn cố ý không can thiệp Win32 thật để bảo đảm an toàn môi trường dev. Cần nghiệm thu riêng trên máy lab chuyên dụng.
  • Windows Application Control Chặn Nạp DLL: Trên môi trường Windows có bật WDAC/AppLocker, việc Playwright khởi động API từ đường dẫn Release bị chặn nạp DLL; cần chạy qua lệnh Development.
  • Chưa Có Docker Daemon Để Test PostgreSQL & SSH Thật: Máy trạm hiện tại không có Docker daemon đang chạy, nên chưa thể diễn tập restore PostgreSQL thật hoặc thử nghiệm SSH với container VPS Linux thực tế.
  • Chưa Có Xác Thực Đa Yếu Tố (MFA): Hệ thống hiện mới hỗ trợ mật khẩu PBKDF2 và session cookie HttpOnly; luồng xác thực MFA (TOTP / FIDO2) là hạng mục cần bổ sung tiếp theo.
  • Giới Hạn Bảo Vệ Audit: SentinelDbContext.SaveChanges chặn entity AuditLog Modified/Deleted khi ghi qua DbContext này. Đây không phải interceptor hoặc bảo vệ DB-level; chưa có kho WORM hoặc SIEM bên ngoài.
  • Chưa Tự Động Luân Chuyển Khóa (Key Rotation): Master Vault Key của VPS và Device Secret của Agent hiện là khóa tĩnh; chưa có cơ chế xoay vòng khóa tự động theo chu kỳ 90 ngày.
