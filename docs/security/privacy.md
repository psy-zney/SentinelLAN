# Privacy and telemetry disclosure

Only authorized technical endpoint telemetry is collected:

- UTC server heartbeat time and online/offline status (offline after two minutes; self-service notification reconciliation every 15 seconds).
- System CPU utilization sampled between readings, physical RAM utilization, and the system/root volume's used disk percentage.
- Declared device name, OS description, and Agent version.
- Hardware serial/manufacturer/model, CPU name, RAM/system disk capacity, and active private/link-local LAN IP/MAC.
- Antivirus, all three firewall profiles and system-drive encryption status; missing permission is Unknown, and Linux Windows-only checks are NotSupported.
- Presence/version only for MSI ProductCode/UpgradeCode rules configured by the organization; no full personal application list.

New Agent samples carry `collectedAt` separately from the server receipt time. Telemetry API responses expose `collectedAt` and `receivedAt`; the compatibility `createdAt` field uses collection time when available so history and charts place offline samples correctly. Legacy samples have an unknown collection time and use server receipt time. The server rejects collection times older than two hours or more than two minutes in the future. Heartbeat availability still uses receipt time.

Telemetry and heartbeat rows have a 30-day retention policy. A worker deletes expired technical rows in bounded batches every minute; telemetry reads exclude observations outside that window even during cleanup catch-up. Audit, support messages, attachments, and command results have separate lifecycles and are not removed by this worker. Backup retention must be managed separately by the operator.

On Windows, CPU uses GetSystemTimes and RAM uses GlobalMemoryStatusEx. On Linux, the collector reads aggregate /proc/stat and MemTotal/MemAvailable from /proc/meminfo. Windows hosts with more than 64 logical processors require additional processor-group support; Linux container/cgroup-specific accounting is not implemented.

Technical telemetry does not contain keystrokes, screen content, personal file contents, browsing activity, audio/video, network payloads, or authentication secrets. Support requests may contain text, chat messages, and JPEG/PNG images that an employee explicitly selects or photographs, previews, and sends to IT. Images are limited to 2 MiB, available only through authenticated tenant-scoped request endpoints, and never captured automatically by the Agent. Employees should avoid including passwords or personal documents in an image. Credentials are used separately for authentication; the server stores original secret hashes and encrypted dedicated per-device HMAC request keys. The Development Agent identity file is not yet protected by the OS.

The self-service module also stores request status, command results, appointment times, announcement acknowledgements, in-app notifications, and an opt-in mobile push token. Push text on the lock screen is generic; request details require signing in. Maintenance verification codes are stored as keyed hashes and are never included in push or audit records. Heartbeat loss may trigger a notification after the normal offline threshold; it cannot establish why the Agent stopped reporting. Support images and chat remain stored until the organization applies its retention procedure; automatic expiry is not currently implemented.

In Production, the Windows Agent encrypts identity with DPAPI; the Linux Agent uses a unique operator-managed key with AES-GCM and restrictive file permissions. The Development identity file remains unprotected and must not be reused for deployment. Employee users can see their assigned device, policy name (device assignment overrides department default), technical observations, configured software checks and related audit events. OS policy enforcement requires the configured supported adapter and local permissions. Tenant boundaries use explicit query scopes and EF Core global query filters for tenant-owned entities. Trusted initialization, authentication, and workers may run without a current tenant. Legacy Platform roles and routes are retired; trusted workers retain explicit organization predicates. This disclosure describes implemented behavior and does not certify regulatory compliance.

References: [GetSystemTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes), [GlobalMemoryStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex), [Linux proc documentation](https://docs.kernel.org/filesystems/proc.html).

Inventory is refreshed on enrollment/startup and periodically. Software scans run about every 15 minutes or after an authorized refresh/install; displayed observations become unknown when stale. Technical retention includes old security events/software reports after 30 days; image/chat retention still requires the organization procedure. Optional S3/MinIO objects are AES-GCM encrypted with tenant/request/attachment AAD; authorized downloads stay behind the API. Redis wake signals carry no command payload or secret. These observations are self-reported by the endpoint, not proof against a compromised host.
