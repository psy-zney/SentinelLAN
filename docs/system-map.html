01 / Bối cảnh thống nhất

Các chủ thể liên kết thế nào?

Máy Admin và máy nhân viên có thể cùng ở LAN. Người dùng có thể truy cập dịch vụ từ mạng được cấp phép qua HTTPS. Agent trên máy được quản lý chủ động kết nối ra API; PostgreSQL chỉ nằm phía server.

Hai vai trò của “VPS” được phân biệt rõ: VPS chạy hệ thống là hạ tầng; VPS được quản lý qua SSH là tài sản tùy chọn. Chúng có thể là các máy khác nhau.

QUẢN TRỊ

Admin/Technician

Thao tác qua web, có quyền theo vai trò và tổ chức. Lệnh gửi Agent phải có lý do, xác nhận, thời hạn và nonce; lệnh Agent hiện được mô phỏng.

THIẾT BỊ

Agent trên máy được quản lý

Đăng ký bằng token một lần, nhận credential riêng, gửi CPU/RAM/đĩa, OS và phiên bản Agent. Không đọc màn hình, bàn phím, tệp cá nhân hay gói tin mạng.

NHÂN VIÊN

Web và mobile

Chỉ thấy máy được gán trong tổ chức, quét tem QR để xác minh và gửi incident. Mobile không phải phần mềm quản lý điện thoại.

02 / Vòng đời thiết bị

Hệ thống hoạt động theo một luồng chính

Một thiết bị đi từ được cấp phép tới theo dõi, gán người dùng, hỗ trợ sự cố và thu hồi. Các màn hình đều dùng dữ liệu do cùng API kiểm tra quyền.

01 · Cấp phép

Admin tạo tài khoản và token enrollment một lần, có hạn. Cài Agent trên máy được tổ chức cho phép.

02 · Đăng ký

Agent gửi token qua HTTPS. API sử dụng token và trả device ID cùng credential riêng; server lưu hash.

03 · Theo dõi

Agent gửi heartbeat có idempotency key và telemetry kỹ thuật. API lưu PostgreSQL, đẩy trạng thái qua SignalR.

04 · Sử dụng

Admin gán máy; nhân viên xem trên web/mobile, quét QR và gửi incident. Technician xử lý theo quyền.

05 · Kiểm soát

Admin thu hồi credential, audit ghi tác vụ. Lệnh Agent xác minh chữ ký, nonce và hạn trước khi trả kết quả mô phỏng.

“Ping” ở đây là heartbeat tầng ứng dụng qua HTTPS, không phải ICMP ping. Trạng thái online cho biết lần Agent liên hệ API; cần kiểm tra riêng mạng và thiết bị thực tế trước khi khẳng định luồng vận hành đã nghiệm thu.
03 / Cơ chế bảo mật riêng

Chống xâm nhập ở từng ranh giới

SentinelLAN giảm nguy cơ giả mạo truy cập, vượt quyền và phát lại lệnh. Phần cứng, hệ điều hành và đường mạng vẫn cần các biện pháp vận hành riêng; Agent hiện không phải EDR/antivirus/IDS.

Máy Admin bị truy cập từ bên ngoài

  • Web yêu cầu đăng nhập; mật khẩu lưu bằng PBKDF2-SHA256 với 600.000 vòng.
  • Session dùng cookie HttpOnly, SameSite Strict, Secure ở Production; refresh token xoay vòng và có thể thu hồi.
  • Thao tác ghi bằng cookie yêu cầu header chống CSRF; API kiểm tra quyền, tenant, rate limit và audit.

Giới hạn: malware hoặc người điều khiển máy Admin đã đăng nhập có thể thao tác theo quyền phiên. Cần cập nhật OS, MFA nếu bổ sung, khóa màn hình, EDR và phân quyền tối thiểu ở môi trường triển khai.

Máy nhân viên bị truy cập từ bên ngoài

  • Agent chủ động kết nối outbound; không có kênh điều khiển inbound tới Agent trong luồng lõi.
  • Mỗi Agent có credential riêng; thu hồi thiết bị làm credential cũ không còn hợp lệ.
  • Lệnh chỉ thuộc allow-list, ký HMAC, có device ID, hạn và nonce để chặn sửa/phát lại.

Giới hạn: Agent không chặn malware, khai thác lỗ hổng Windows hay truy cập SMB/RDP trái phép. Firewall, cập nhật OS và bảo vệ endpoint phải do hạ tầng triển khai.

Đường mạng và VPS chạy hệ thống

  • Reverse proxy Production nhận HTTPS; HTTP/80 chuyển hướng sang 443. API và PostgreSQL không công bố trực tiếp trong stack Production.
  • TLS bảo vệ dữ liệu trên đường truyền tới proxy; API kiểm tra danh tính, quyền và OrganizationId trước khi đọc/ghi.
  • Endpoint nhạy cảm có rate limit; heartbeat và incident dùng idempotency để tránh ghi trùng khi retry.

Giới hạn: bảo vệ DDoS, quản lý chứng chỉ, firewall VPS, backup/restore và giám sát xâm nhập là trách nhiệm triển khai. Kết nối nội bộ container không phải mã hóa đầu cuối.

Mobile và VPS được quản lý qua SSH

  • Mobile nhân viên giữ access token trong RAM, refresh token trong SecureStore; API kiểm tra quyền máy được gán.
  • QR được phân tích trên thiết bị; ứng dụng gửi mã QR tới API, không gửi ảnh camera trong luồng hiện tại.
  • SSH tới VPS tùy chọn dùng host-key fingerprint đã pin; private key mã hóa AES-256-GCM ở server, thao tác restart có quyền, lý do, xác nhận và nonce.

Giới hạn: chưa có app native Admin và chưa có bảo đảm phòng chống thiết bị mobile đã root/jailbreak. Khóa vault và fingerprint SSH phải được quản lý an toàn ngoài DB.

Không tuyên bố “ngăn mọi xâm nhập”. Dữ liệu PostgreSQL không được mã hóa từng dòng bởi ứng dụng; tenant isolation là kiểm tra trong service/truy vấn, chưa có PostgreSQL row-level security. Audit chặn sửa/xóa qua EF Core nhưng chưa phải WORM độc lập.

Ví dụ heartbeat JSON

{
  "idempotencyKey": "7f82b915de0644d3a6781d04c2be4017",
  "cpuPercent": 21.5,
  "ramPercent": 48.2,
  "diskPercent": 63.0,
  "osVersion": "Windows 11",
  "agentVersion": "0.1.0"
}

Định dạng request JSON là application/json theo HTTP client của .NET và ứng dụng. Khi mất mạng, Agent Production xếp tối đa 50 mục telemetry trong tối đa 1 giờ; file hàng đợi được bảo vệ bằng Windows DPAPI hoặc AES-GCM trên Linux. Đây là file cục bộ để retry, không phải tệp gửi lên. Credential/nonce/kết quả chờ của Agent cũng được bảo vệ ở nơi lưu cục bộ. Không có mã hóa đầu cuối riêng cho toàn bộ JSON ngoài TLS.

Nếu sau này cần gửi tệp đính kèm, phải thiết kế riêng: danh sách MIME/đuôi được phép, giới hạn dung lượng, quét malware, checksum, quyền theo tenant, mã hóa lưu trữ, thời hạn lưu và audit. API hiện tại chưa có hợp đồng upload tệp để chọn “định dạng bắt buộc”.

Mũi tên biểu thị quan hệ nghiệp vụ giữa các bảng. SQL hiện tại tạo 25 bảng (gồm bảng lịch sử migration) qua 14 migrations nhưng chưa khai báo foreign key vật lý; tính toàn vẹn liên bảng đang phụ thuộc kiểm tra của ứng dụng. Xem migration SQL để xác nhận constraint và index chính xác.

Tải SQL PostgreSQLERD Mermaid đầy đủTừ điển dữ liệu

Tệp schema.postgresql.sql là script idempotent từ toàn bộ EF Core migrations, gồm DDL, index, thay đổi schema và bảng lịch sử migration. Tạo lại sau khi thêm migration:

dotnet ef migrations script --idempotent \
  --project apps/backend/src/SentinelLAN.Infrastructure \
  --startup-project apps/backend/src/SentinelLAN.Api \
  --output docs/database/schema.postgresql.sql

Chỉ chạy script trên PostgreSQL đã sao lưu và trong quy trình triển khai được duyệt. Script định nghĩa schema, không chứa dữ liệu demo hoặc mật khẩu.
